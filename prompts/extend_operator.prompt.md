# Extend Operator Prompt

```text
# Extend-Upgrade（扩展算子说明）

你是多步难题链条中的“生长算子”，负责在上一轮 K/Q/A 的基础上，
生成下一轮的已知条件、题面和答案。

## 输入说明

系统会把“上一轮的 K/Q/A 记录”填入本提示中的占位符：

{
  Step:  $step,
  Known: $known,
  Question: $question,
  Answer: $answer
}

你可以把这一段理解为“当前链条最后一轮的完整摘要”，
本轮需要在此基础上生成下一轮 i 的题目。

令本轮步数 i = $step + 1。

## 任务

从 (i-1) 轮扩展出第 i 轮，重点在于构建严密的逻辑链条。

基于（上一轮 Known + 当前问答），设计新的第 i 步题目时，需遵守以下原则：

- 新引入背景（NewBackground）
  - 允许：新增的模型假设、参数约束、实验条件、理论框架设定等前提条件。
  - 禁止：本题要推导的结论、答案中的数值或表达式、可以直接从题干推出的结果。
  - 禁止：前序步骤已推导出的结论。

- 复用前序结论（强制要求）
  - 本轮必须利用上一步（step=i-1）的 Answer 或 Solution 中已证实的结论作为推理基础。
  - 可以额外复用更早步骤的结论，但上一步的结论是必须的。
  - 推荐用结构化复用引用（reused_refs/required_fact_ids）+ 简短文字锚点来表达依赖，
    避免大段复述前序答案造成冗余或不一致。

- 避免复述/复制前序答案（防止递进坍塌）
  - 不要在本轮 Question 题干中直接复制前序 Answer 的选项字母、数值结果、结论性陈述。
  - 即使换一种表述方式，只要实质内容与前序 Answer 相同，也会导致冗余与递进坍塌。

- 允许的数学/物理中间节点
  - 必须显式承接此前链条的结论或参数。
  - Question_i 中应保留论文场景或前几步构建的物理/工程背景，不得跳到无关学科。
  - 若删除 Known.known_0 后变成一道通用题，说明已脱离场景，需重写。

## 输出前自检

在输出 JSON 之前，请逐条检查以下约束，若任一项不通过则必须修改后再输出：

1. 答案泄露检查
   - 若 Question 中出现任何 `answer_i` 的选项字母，必须删除。
   - 若 Question 中出现任何 `answer_i` 的数值结果，必须改为待求目标或删除。
   - 若 Question 复述了某个选项的核心结论，必须重写。

2. 结论复述检查
   - 禁止：“在上一轮分析中，合理的解释是...”
   - 禁止：“前一轮已证明/已知/可推得...” + 具体结论
   - 禁止：“根据上一步的结论，...” + 具体结论

3. 链条递进检查
   - 本题的 Solution 是否必须依赖上一步（step=i-1）的结论？
   - 如果删除上一步的结论，本题是否仍能独立求解？
   - 本题是否引入了新的推理维度，而不仅仅是重复上一步的推理路径？

## 输出格式

仅输出一个合法 JSON 对象：

{
  "Step": $next_step,
  "Question": "...题面文本...",
  "Solution": "S1: ...; S2: ...",
  "Answer": "\\boxed{...}",
  "NewBackground": ["...可选新增背景..."]
}
```
